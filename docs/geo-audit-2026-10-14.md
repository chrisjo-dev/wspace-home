## 잘 되어 있는 것

- 4쪽 모두 서버에서 완성된 HTML이라 JS를 실행하지 않는 AI 크롤러도 다 읽는다.
- robots.txt 전체 허용, sitemap 지정, 자기 자신을 가리키는 canonical, 진짜 404, http와 www 없는 주소의 301 이동.
- HTTPS와 HSTS, HTML gzip 1~3KB, 응답 0.2~0.4초.
- 개인정보처리방침이 구체적이고(시행일, 국외 위탁, 광고 쿠키), 소개 페이지에 AI 사용과 사실 확인 원칙을 공개했다.

## 조치 우선순위

### 1순위: 바로, 효과가 크고 쉬움

1. **홈과 /about/에 JSON-LD 넣기.** WebSite, Person(Chris Jo), 하위 사이트 4곳 연결(hasPart), /about/에는 AboutPage와 BreadcrumbList. 붙여 넣을 예시는 부록 schema.md에 있고 파싱 오류가 없음을 확인했다.
2. **외부 프로필 연결(sameAs).** 지금 정직하게 넣을 수 있는 것은 블로그에 걸린 GitHub `chrisjo-dev` 하나다. GitHub 프로필 웹사이트 칸에 `https://www.wspace.ai.kr/`를 넣으면 양방향으로 연결된다. "wspace"는 같은 이름이 많아(코워킹 공간, 대학 시설, 게임 용어) 이 연결이 구분에 특히 중요하다.
3. **OG 태그 보강.** 모든 쪽에 og:image, og:site_name, og:locale, twitter:card. 소개, 개인정보, 연락처 쪽에는 OG가 아예 없다.
4. **llms.txt 추가.** 루트와 하위 사이트 모두 404다. 허브용 템플릿은 부록 ai-visibility.md에 있다.
5. **sitemap에 lastmod.** 홈은 하루 두 번 바뀌는데(update.yml) 이 신호가 빠져 있다. update.yml이 갱신할 때 같이 고치면 된다.

### 2순위: 이번 달

6. **소개 페이지 본문 보강.** 운영자 경력 3~4문장, 사이트 운영 사실(시작일, 누적 지문 수, 만드는 방식), 질문형 소제목과 40~60단어 답, 눈에 보이는 수정일.
7. **폰트 경량화.** Pretendard 전체 글자 파일을 굵기 4종 받아 최대 약 3.1MB다. 필요한 글자만 받는 dynamic-subset 판으로 바꾸고 cdnjs에 preconnect.
8. **파비콘 추가.** favicon.ico와 apple-touch-icon이 404다.
9. **검색엔진 등록.** Bing Webmaster(ChatGPT 검색이 Bing 색인을 씀), 네이버 서치어드바이저. 배포 때 IndexNow 호출도 고려.

### 3순위: 장기

10. **외부 언급 만들기.** 외부 검색에서 wspace.ai.kr 언급이 확인되지 않았다(미국 기준 검색이라 한국어 결과는 덜 반영됐을 수 있음). 블로그 글을 커뮤니티나 개발자 플랫폼에 소개할 때 "wspace.ai.kr"로 표기.
11. **보안 헤더.** GitHub Pages는 응답 헤더를 못 바꾼다. referrer 정책 정도는 meta로 넣고, 전부 갖추려면 Cloudflare 프록시가 필요하다. 지금 단계에서는 급하지 않다.

| AboutPage | 없음 | 중간 | 소개 페이지가 운영자 엔티티를 설명한다는 신호가 없음 |
| Article + dateModified | 해당 적음 | 낮음 | 허브 페이지에는 글이 없음. 블로그 하위 사이트에서 다룰 항목 |
| speakable | 없음 | 낮음 | 홈 소개 문단이 짧고 자족적이라 대상으로 쓸 수는 있으나, Google 지원은 뉴스 게시자 대상 베타라 우선순위 낮음 |
| BreadcrumbList | 없음 | 낮음 | `/about/` 등 2단계 페이지에 단순 적용 가능 |
| WebSite + SearchAction | 해당 없음 | 낮음 | 사이트 내 검색 기능이 없음. 없는 검색을 선언하면 안 되므로 넣지 않음. Google도 sitelinks 검색창 표시를 2024년 11월에 중단함 |

## 4. sameAs 엔티티 연결

**현재 sameAs 링크:** 0개

| 플랫폼 | 연결 | 근거 |

| Wikidata | 아니오 | 해당 항목 없음 |
| LinkedIn | 아니오 | 사이트 어디에도 링크 없음 |

| Crunchbase | 아니오 | 해당 없음 |
| Twitter/X | 아니오 | 링크 없음 |
| GitHub | 아니오(후보 있음) | `blog.wspace.ai.kr` 프로필 영역이 `https://github.com/chrisjo-dev`로 링크함(HTTP 200 확인) |

정직하게 넣을 수 있는 sameAs는 현재 **GitHub 1개**입니다. 단, 확인 결과 이 GitHub 계정의 공개 `name`은 `chrisjo`, `blog` 필드는 비어 있어 GitHub 쪽에서 wspace로 되돌아오는 링크가 없습니다. 운영자 본인 계정이 맞는지 최종 확인하고, GitHub 프로필의 Website 칸에 `https://www.wspace.ai.kr/`를 넣어 양방향으로 만드는 것을 권장합니다. LinkedIn 등 다른 프로필은 실제로 공개할 의사가 있을 때만 추가해야 하며, 공개하지 않는 계정을 넣으면 안 됩니다. 자기 소유 하위 사이트(blog 등)는 sameAs가 아니라 `WebSite`의 관계(`hasPart`)로 표현합니다.

## 6. JavaScript 렌더링 위험

**Schema 전달 방식:** 해당 없음(현재 schema 없음). 페이지 본문은 서버가 보낸 정적 HTML이라 AI 크롤러가 그대로 읽습니다. 아래 JSON-LD도 정적 HTML의 `<head>`에 직접 넣으면 위험이 없습니다. 홈의 "오늘의 외국어 지문", "최근 블로그 글" 목록도 원본 HTML에 들어 있음을 확인했습니다(빌드 시 생성으로 보임).

## 8. 권장 JSON-LD

아래 두 블록은 사이트 본문에 이미 공개된 사실만 사용했습니다. `@id`로 같은 Person, WebSite 엔티티를 두 페이지에서 공유합니다. 두 블록 모두 `python3 -m json.tool`로 파싱을 확인했습니다.

### 8-1. 홈 `/` (WebSite + Person + WebPage)

`index.html`의 `<head>` 안에 넣습니다.


### 8-2. 소개 `/about/` (AboutPage + Person + BreadcrumbList)

`about/index.html`의 `<head>` 안에 넣습니다. Person 내용은 홈과 같은 `@id`로 맞췄습니다(한쪽을 고치면 다른 쪽도 같이 고칩니다).

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "AboutPage",
      "@id": "https://www.wspace.ai.kr/about/#webpage",
      "url": "https://www.wspace.ai.kr/about/",

      "inLanguage": "ko-KR",
      "isPartOf": { "@id": "https://www.wspace.ai.kr/#website" },
      "about": { "@id": "https://www.wspace.ai.kr/#website" },
      "mainEntity": { "@id": "https://www.wspace.ai.kr/#person" },
      "breadcrumb": { "@id": "https://www.wspace.ai.kr/about/#breadcrumb" }
    },
    {
      "@type": "Person",
      "@id": "https://www.wspace.ai.kr/#person",
      "name": "Chris Jo",
      "url": "https://www.wspace.ai.kr/about/",
      "email": "mailto:wonsang.dev@gmail.com",

      "knowsAbout": ["클라우드 인프라", "DevOps", "GitOps", "Kubernetes", "CI/CD", "로컬 AI 모델"],
      "sameAs": [
        "https://github.com/chrisjo-dev"
      ]
    },
    {
      "@type": "WebSite",
      "@id": "https://www.wspace.ai.kr/#website",
      "url": "https://www.wspace.ai.kr/",
      "name": "wspace",

        { "@type": "ListItem", "position": 1, "name": "wspace 홈", "item": "https://www.wspace.ai.kr/" },
```

`/privacy/`, `/contact/`도 같은 방식으로 `WebPage`(contact는 `ContactPage`) + `BreadcrumbList` 두 항목만 넣으면 충분합니다.
