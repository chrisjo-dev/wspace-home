맥북에서 Whisper로 한국어 음성을 로컬에서 텍스트로 바꾸기

글 Chris Jo, 2026년 10월 22일 작성

이 글은 누구를 위한 글인가

녹음 파일을 텍스트로 바꾸고 싶은데 외부 음성 인식 서비스에 올리기는 꺼려지는 맥북 사용자를 위한 글입니다. 저는 면접을 준비하며 STAR 기법으로 쓴 답변을 소리 내어 연습하고, 녹음한 답변을 글로 다시 읽어 보고 싶었습니다. 클로바노트나 다글로 같은 서비스도 있지만 녹음에 회사명과 프로젝트 세부 내용이 들어 있어서 밖으로 보내고 싶지 않았습니다. 그래서 OpenAI의 Whisper 모델을 Apple Silicon 맥북에서 직접 돌렸고, 그 과정을 순서대로 정리했습니다.

설치부터 첫 변환까지는 10분 정도면 됩니다. 이 글에는 설치 순서와 함께 모델 크기를 고르는 기준, 매일 반복하는 변환을 덜 번거롭게 만든 방법까지 담았습니다.

먼저 세 가지를 구분합니다

로컬에서 AI 모델을 돌릴 때는 실행 엔진, 모델 가중치, 입력 전처리를 따로 생각하면 헷갈리지 않습니다.

구분이 글에서 쓰는 것역할
실행 엔진whisper.cpp모델을 불러와 돌리는 프로그램. Whisper를 C++로 다시 구현해 Apple Silicon의 Metal GPU 가속을 씁니다
모델ggml 형식 Whisper 가중치실제로 음성을 알아듣는 부분. 엔진과 따로 내려받습니다
전처리ffmpeg녹음 파일을 엔진이 받는 형식으로 바꿉니다

Ollama로 LLM을 돌려 본 적이 있다면 흐름이 거의 같습니다. Ollama가 엔진이고 내려받는 모델이 따로 있듯이, whisper.cpp도 엔진일 뿐이라 설치만 해서는 아무것도 변환하지 못합니다. 참고로 whisper.cpp를 만든 Georgi Gerganov는 Ollama 내부 엔진인 llama.cpp를 만든 개발자이기도 합니다.

1단계. 엔진과 ffmpeg 설치

brew install whisper-cpp
brew install ffmpeg

whisper.cpp는 16kHz WAV만 입력으로 받기 때문에 m4a나 mp3 녹음을 바꾸려면 ffmpeg가 필요합니다.

실행 파일 이름은 설치된 버전에 따라 다를 수 있습니다. 제 블로그 원글의 설치 절에서는 whisper-cpp라는 이름으로 실행했고, 나중에 만든 자동화 도구에서는 whisper-cli를 불렀습니다. 이 글을 쓰며 확인한 Homebrew 버전(whisper.cpp 1.8.4)에는 whisper-cli가 설치되어 있었습니다. 설치 후 which whisper-cli로 먼저 확인하고, 이 글의 명령도 그 이름으로 적었습니다.

2단계. 모델 크기 고르기

모델파일 크기한국어 품질속도
tiny75MB낮음매우 빠름
base142MB낮음빠름
small466MB보통보통
medium1.5GB양호느림
large-v33GB가장 좋음매우 느림

한국어라면 medium부터 시작하기를 권합니다. small 이하에서는 한국어 인식률이 눈에 띄게 떨어졌습니다. M 시리즈 맥북이라면 medium도 무리 없이 돌아갑니다. 동작만 빨리 확인하고 싶을 때 small을 쓰고, medium 결과가 부족할 때 large-v3로 올립니다.

mkdir -p ~/.whisper
curl -L -o ~/.whisper/ggml-medium.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-medium.bin

다른 크기를 받을 때는 주소와 파일 이름의 ggml-medium.bin만 ggml-small.bin이나 ggml-large-v3.bin으로 바꿉니다.

3단계. 녹음 파일을 16kHz 모노 WAV로 바꾸기

ffmpeg -i input.m4a -ar 16000 -ac 1 output.wav

-ar 16000은 샘플레이트를 16kHz로, -ac 1은 채널을 모노로 바꾸는 옵션입니다. mp3도 입력 파일 이름만 바꾸면 같은 명령으로 됩니다. 변환이 안 될 때 엔진이나 모델을 의심하기 전에 이 단계부터 확인합니다.

4단계. 텍스트로 변환하기

whisper-cli -m ~/.whisper/ggml-medium.bin -l ko -f output.wav > result.txt

-m은 모델 파일, -f는 입력 WAV, -l ko는 언어입니다. 언어를 빼면 자동으로 감지하지만, 한국어라고 정해 주는 편이 더 정확했습니다.

한 번에 돌리는 순서

녹음 파일 하나를 처리하는 전체 흐름은 네 줄입니다. 마지막에 임시 WAV를 지우는 것까지 한 묶음으로 기억해 두면 디스크에 변환 파일이 쌓이지 않습니다.

ffmpeg -i 녹음파일.m4a -ar 16000 -ac 1 temp.wav
whisper-cli -m ~/.whisper/ggml-medium.bin -l ko -f temp.wav > result.txt
cat result.txt
rm temp.wav

다른 로컬 모델에도 같은 순서가 통합니다

이 작업을 하게 된 이유 중 하나는 DevOps 엔지니어로서 모델이 실제로 어떤 런타임 위에서 도는지 직접 만져 보고 싶어서였습니다. 그 전에 Ollama로 Qwen-VL을 돌려 보면서 생각보다 많은 모델이 개인 맥북에서 쓸 만하게 돌아간다는 것을 알았고, 음성 인식도 그런지 궁금했습니다.

해 보니 순서는 LLM과 같았습니다. 엔진을 설치하고, 모델을 내려받고, 입력 형식을 맞추고, 실행합니다. 고민할 거리도 같습니다. 모델 크기와 장비 성능 사이에서 어디까지 타협할지, 입력 전처리를 얼마나 정확히 맞출지, 어떤 모델을 고르느냐가 품질을 얼마나 바꾸는지입니다. 새 모델을 로컬에서 돌릴 때 이 네 단계 중 어디서 막혔는지부터 나눠 보면 원인을 빨리 찾을 수 있습니다.

실제로 겪은 문제와 해결

고유명사가 자주 틀립니다

medium 모델의 한국어 인식은 기대보다 괜찮았습니다. 발음이 또렷하고 배경 소음이 적으면 그대로 써도 될 수준이었습니다. 다만 회사명이나 기술 용어 같은 고유명사는 자주 틀렸습니다. 변환 결과를 바로 쓰지 않고 한 번 읽으며 고치는 과정을 꼭 넣습니다.

인식률이 낮을 때

두 가지를 봅니다. 하나는 모델 크기로, small에서 medium, medium에서 large-v3 순으로 올려 봅니다. 다른 하나는 녹음 상태입니다. 배경 소음과 마이크 거리가 인식률에 큰 영향을 줬습니다.

같은 명령을 하루에 서너 번 치게 됩니다

실제로 쓰기 시작하자 녹음하고, 터미널을 열고, ffmpeg로 바꾸고, whisper-cli를 돌리고, 결과 파일을 여는 일을 하루에 서너 번씩 반복했습니다. 그래서 Flask 서버 하나로 간단한 웹 화면을 만들었습니다.

  1. 브라우저에서 m4a나 mp3 파일을 끌어다 놓습니다.
  2. 서버가 ffmpeg로 16kHz 모노 WAV로 바꿉니다.
  3. whisper-cli가 변환해 txt 파일과 srt 자막 파일을 만듭니다.
  4. 서버가 두 파일을 읽어 JSON으로 돌려줍니다.
  5. 브라우저에서 결과를 보고, 복사하고, 내려받습니다.

파일은 Python의 tempfile로 만든 임시 폴더에서만 다루고 요청이 끝나면 지웁니다. 로컬에서만 도는 도구라 녹음이 밖으로 나갈 일이 없습니다. 만드는 데 든 시간보다 만들지 않고 버틴 시간이 더 길었습니다. 같은 명령을 세 번째 칠 때가 자동화를 시작할 때였습니다.

체크리스트

  • which whisper-cli로 실행 파일 이름을 확인했다.
  • 엔진과 별도로 모델 파일을 내려받았고 경로를 알고 있다.
  • 한국어라면 medium 이상 모델을 쓴다.
  • 입력은 16kHz, 모노, WAV다.
  • -l ko로 언어를 정해 줬다.
  • 결과의 고유명사를 사람이 한 번 검수한다.
  • 인식률이 낮으면 녹음 환경과 모델 크기를 차례로 바꿔 본다.
  • 같은 변환을 자주 한다면 임시 파일을 지우는 작은 자동화를 만든다.
